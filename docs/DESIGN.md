# Design notes

## The loop, and why each step exists

```
join -> graveyard assigned -> buy brains on the belt -> income ticks
   ^                                                        |
   |                                 rebirth <---- bank $1M |
   |                                                        v
   +---- lock gate / claw thieves <---- rivals try to steal them
```

Four things are competing for the player's attention at all times: **income**
(buy more brains), **risk** (your graveyard is open while you're away from it),
**opportunity** (someone else's graveyard is open right now), and **prestige**
(rebirth resets everything for a permanent multiplier). The carry mechanic is
what ties them together — stealing takes you *away* from your own base, so
greed is self-punishing.

## World layout

Everything is generated by `WorldBuilder` around the origin. The conveyor runs
down the middle on the Z axis, graveyards face it from both sides, and the two
"destination" structures cap each end.

```
                              +Z
                   [Graveyard 7]   [Graveyard 8]
                   [Graveyard 5]   [Graveyard 6]
                            Crypt of Rebirth  (z = +95)
                                 |
                   [Graveyard 3] | belt | [Graveyard 4]
                   [Graveyard 1] | z-60 | [Graveyard 2]
                                 | ..+60|
                            Leaderboard      (z = -95)
                            Spawn gates      (z = -130)
                              -Z
```

Odd-numbered graveyards sit at `x = -80`, even ones at `x = +80`, four rows deep
at `z = -108, -36, +36, +108`. Each plot's CFrame faces the belt, so every plot
script can work in local space: `-Z` is always "toward the gate", and the eight
grave slots are laid out in two rows of four behind it.

The belt would otherwise split the plaza in two, so it has crossings at
`z = +-22`: gaps in the rails with a pair of shallow ramps either side, flush with
the belt surface. Brains ride straight through anyone standing on a crossing,
since brain parts have collisions off.

Each graveyard has: a dirt floor, walls with a single 18-stud entrance, a
ForceField gate that only materialises when locked, a sign above the entrance
(owner, income/s, brains, lock status), a lock pad just inside, and eight
podium + headstone pairs.

## Economy

Income is per-second and paid every second by `EconomyService`:

```
income = sum(brain.Income * variant.IncomeMultiplier) * (1 + rebirths * 0.25)
```

### Why Gold and Rainbow matter

Variants have *worse* payback (Gold pays 4x the price for 3x the income,
Rainbow 12x for 8x) but that is the wrong way to read them. The scarce resource
is **grave slots**, not cash — only eight brains can ever earn for you at once.
So income *per slot* is what actually gates progression, and a Rainbow brain is
8x better per slot than its standard twin. That is what makes a lucky belt roll
worth sprinting for, and worth stealing.

Spawn weights (from rarity) and variant weights are independent rolls:

| Rarity | Weight | Share |
| --- | --- | --- |
| Common | 1000 | 52.5% |
| Uncommon | 520 | 27.3% |
| Rare | 240 | 12.6% |
| Epic | 100 | 5.3% |
| Legendary | 34 | 1.8% |
| Mythic | 10 | 0.5% |
| Godly | 3 | 0.16% |
| Secret | 1 | 0.03% |

Weights are per brain, and every band holds two brains except Secret, which holds
one — that is why Secret's share is half of what its weight suggests. A specific
Godly brain lands about 1 in 1,270 belt spawns; The Big Rotto, about 1 in 3,800.

### Scrapping

Scrapping returns 25% of a brain's price. It exists purely so a full graveyard
can still make progress — without it, a board of eight Commons with no cash is
a soft dead end, since buying and stealing both require a free slot.

## Risk and defence

| Lever | Value | Why |
| --- | --- | --- |
| Steal hold | 6s | Long enough that a defender who is home can react |
| Carry speed | 70% | The thief is slower than whoever is chasing them |
| Carry visibility | Name tag over the head | You can spot a thief across the plaza |
| Gate lock | 30s + 6s per rebirth (max 120s) | Enough to buy a brain or two, not enough to idle behind |
| Lock cooldown | 60s | Locking is a decision, not a default state |
| Claw range / stun | 11 studs / 3s | Rewards intercepting rather than chasing forever |

Losing a carried brain returns it to the exact grave it came from where possible,
and to any free grave of the original owner otherwise. Death, disconnecting and
rebirthing all count as dropping it. Locking the gate also ejects anyone who is
already inside, so a locked graveyard can never trap a thief.

## Rebirth

```
requirement(r) = $1,000,000 * 4^r      -- $1M, $4M, $16M, $64M ...
income bonus   = 1 + 0.25 * r
lock duration  = min(30 + 6r, 120) seconds
```

Rebirth clears cash to the $250 starting stake and destroys every brain, so the
multiplier has to earn itself back. Capped at 20, which is well past the point a
board of Secrets can fund.

## Persistence

`DataService` stores one key per player (`player_<UserId>`) in the
`RottingBrains_Profiles_v1` DataStore:

```lua
{
  Cash, Rebirths, TotalEarned,
  Slots = { { Slot, BrainId, VariantId, ColorIndex }, ... },
  Stats = { Purchased, Stolen, Lost, Rebirths },
}
```

Services that own live state register a save hook rather than writing to the
DataStore themselves — `PlotService` uses one to snapshot the grave slots before
every save, which is what makes autosave, leave-save and `BindToClose` all
correct without duplicating logic. If a load fails after four attempts the player
gets a playable temporary profile with saving disabled, so a DataStore outage can
never wipe a real save.

Stolen brains are saved as part of whoever holds them, so theft is permanent
until someone steals them back.

## Ideas not built

- Gamepasses and Robux products (2x income, extra grave slots, instant lock refresh)
- A "brain mutation" layer on top of variants (dripping, frozen, radioactive)
- Cross-server `OrderedDataStore` leaderboards
- Custom shamble animations and uploaded audio
- Conveyor speed/rarity scaling with server progression
